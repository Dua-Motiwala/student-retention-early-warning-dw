# Decisions Log: Architecture, Data Modeling, & Implementation Choices
**Project:** University Dropout Early-Warning Warehouse & Retention Dashboard  
**Maintained by:** Senior Data Engineer & BI Developer / Student

---

| Date | ID | Decision | Justification / Reason | Alternatives Rejected |
|:---:|:---:|:---|:---|:---|
| 2026-11-20 | DEC-001 | Implement Lakehouse Medallion pattern across 5 distinct MySQL schemas (`staging`, `bronze`, `silver`, `gold`, `marts`). | MySQL does not natively support object storage Delta Lake formats. Emulating layers via dedicated schemas provides clean boundaries, isolation, and explicit lineage for viva defense. | Single database with table prefixes (e.g. `brz_`, `slv_`), which leads to object clutter and complex permission management. |
| 2026-11-20 | DEC-002 | Store all database credentials in `.env` and access via `python-dotenv`. | Essential security practice; ensures no credentials are leaked when the project is submitted, reviewed, or handed over to another developer. | Hard-coding database passwords in scripts or Jupyter notebooks. |
| 2026-11-20 | DEC-003 | Retain raw CSV files in `data/raw/` as immutable file bronze storage. | Preserves the raw source of truth independent of any database mutations, fulfilling data lake redundancy standards. | Ingesting and deleting CSV files immediately. |
| 2026-11-20 | DEC-004 | Use chunked batch streaming (50k–100k rows/chunk) for `studentVle.csv` (10.6M rows). | Ingesting 453 MB / 10.65M rows in a single DataFrame causes severe memory bloat and risks MySQL connection packet timeouts. | Reading entire file with `pd.read_csv()` into memory. |
| 2026-11-20 | DEC-005 | Standardize relative days into weekly offsets: `week_number = FLOOR(date / 7)`. | OULAD represents time as relative day offsets. Grouping into integer week buckets aligns with academic calendar reporting and eliminates date-conversion errors across leap years. | Converting relative days into arbitrary synthetic calendar dates. |
| 2026-11-20 | DEC-006 | Zero Target Leakage temporal rule for Gold layer feature engineering. | Any feature computed for week $N$ must strictly use data from week $\le N$. Interventions in week 5 cannot use assessments or clicks from week 6. | Using end-of-term semester aggregates for early-warning predictions (unrealistic data leakage). |
| 2026-11-20 | DEC-007 | Native Python backward-chaining expert system with rule justification audit trace. | University advisors require transparent reasoning for interventions ("why is this student flagged?"). Backward chaining resolves risk hypotheses systematically and outputs rule explanations. | Black-box unexplainable deep learning models or simple arbitrary if/else scripts without inference logic. |
| 2026-11-21 | DEC-008 | Object-casting NaN to None in Pandas chunked ingestion (`chunk.astype(object).where(pd.notnull(chunk), None)`). | Native pandas numeric Series retain `float('nan')` which triggers PyMySQL `ProgrammingError: nan can not be used with MySQL`. Converting explicitly to Python `None` ensures valid SQL `NULL` conversions at over 20,000 rows/sec. | Iterating row-by-row via cursor or slow regex replacement. |
| 2026-11-21 | DEC-009 | Implement `staging.stg_vle` as an integrated view over `bronze.raw_student_vle` and `bronze.raw_vle`. | Host disk space on C: drive has ~5.5 GB free. Re-duplicating 10.65M rows physically in both Bronze and Staging would consume an additional ~600 MB of unnecessary I/O. A view presents the identical SQL interface with zero storage overhead. | Physical table duplication of 10.65M rows. |
| 2026-11-21 | DEC-010 | Strict row-count equality check with auto-repair in `etl/02_load_staging_bronze.py`. | Prevents data corruption: only skip ingestion if `existing_cnt == expected_csv_cnt`. If an interrupted load left partial rows, auto-truncate and reload rather than appending duplicates. | Blindly skipping if `cnt > 0` (risks keeping corrupted partial data) or always appending (causes massive duplicate rows). |
| 2026-11-21 | DEC-011 | Preserve raw assessment `score` as NULL while creating `score_clean = 0.00` and `is_missing_score = 1`. | 173 assessment submissions had missing marks. Retaining raw NULL preserves auditability, while imputing 0.00 prevents arithmetic failure during downstream weighted cumulative score calculations in Gold and Marts layers. | Dropping missing score rows (corrupts assessment weight totals) or imputing cohort mean (unrealistically awards free marks to un-scored work). |
| 2026-11-21 | DEC-012 | Impute missing `imd_band` (1,111 rows) as `'Unknown'`. | Preserves full cohort size (32,593 students) so socioeconomic slices in Power BI do not omit students or distort retention rates. | Dropping records with missing IMD bands or arbitrarily forcing students into decile buckets without evidence. |
| 2026-11-21 | DEC-013 | Impute missing `date_registration` (45 rows) with cohort presentation median registration offset. | All 45 students were actively registered; dropping them causes student loss. Imputing cohort median provides a realistic enrollment timestamp without introducing temporal anomalies. | Dropping the 45 students or imputing day 0. |
| 2026-11-21 | DEC-014 | Enforce explicit window deduplication rule `ROW_NUMBER() OVER (PARTITION BY id_student, code_module, code_presentation ORDER BY date_registration DESC)`. | Guarantees primary key uniqueness at the student-course grain across all current and future ingests. (0 duplicates currently found). | Allowing potential composite key collisions. |
| 2026-11-21 | DEC-015 | Classify unregistration consistency into 4 distinct categories (`unregistration_status`). | 10,063 students withdrew normally with dates; 93 withdrew administratively without dates; 9 formally unregistered late but were graded as Fail; 22,428 completed. Explicit categorization provides actionable granularity for university retention advisors. | Forcing a binary withdrawal flag that ignores administrative nuances. |
| 2026-11-21 | DEC-016 | Vectorized chunked in-memory feature engineering in Python for the Gold Layer. | Direct SQL multiple `COUNT(DISTINCT)` and window aggregations across 10.65M rows exhaust MySQL temporary disk space in `C:\Windows\Temp` (error 28). Processing via vectorized pandas/numpy streams in RAM takes only ~25 seconds and consumes 0 temporary disk space. | Letting MySQL create massive uncompressed temporary files on the OS system drive. |
| 2026-11-21 | DEC-017 | Backward directional `asof` merging (`pd.merge_asof(direction='backward')`) for temporal feature alignment. | Strictly guarantees Zero Target Leakage: assessment submissions at week $N$ only integrate assessments submitted on or before week $N$. Prevents future exam/TMA marks from leaking into early dropout warnings. | Joining future end-of-semester marks to predict early-week behavior. |
| 2026-11-21 | DEC-018 | Retain pre-course submission milestones (1,909 banked and 148 early submissions at week < 0). | Banked marks from prior attempts and TMA1 early submissions are valid academic history possessed prior to course start. Preserving them allows the early warning system to credit prior achievements without temporal leakage. | Artificially zeroing or deleting pre-course academic achievements. |
| 2026-11-21 | DEC-019 | Implement Conformed Dimensional Model with dual Star Schemas (`Academic Mart` and `Early Warning Mart`). | Standardizes dimensions (`dim_student`, `dim_course`, `dim_date`, `dim_assessment_type`) across assessment facts and weekly engagement facts, enabling unified cross-filtering and drill-through in Power BI while maintaining clean domain separation. | Building a single monolithic denormalized table (poor BI performance, billions of redundant cells) or siloed non-conformed marts. |
| 2026-11-21 | DEC-020 | Employ integer surrogate keys (`INT/BIGINT UNSIGNED AUTO_INCREMENT`) for all dimension and fact relationships. | Surrogate integer keys maximize join performance and columnar compression in Power BI's VertiPaq engine and MySQL InnoDB, shielding the warehouse from natural composite business key mutations. | Using composite natural string keys (`code_module`, `code_presentation`, `id_student`) for fact table joins. |
| 2026-11-21 | DEC-021 | Extend `dim_date` temporal coverage across all observed weeks (Week -4 to Week 86, 91 rows). | 72 legitimate retrospective/deferred student assessment submissions occurred between Week 39 and Week 86. Including extended weeks prevents referential integrity violations and ensures 0 orphan records without dropping data. | Truncating late submissions beyond week 38 or omitting foreign keys on late submissions. |
| 2026-11-21 | DEC-022 | Reconcile 32,593 enrollments to 28,785 unique student dimension records with `total_courses_enrolled` attribute. | `dim_student` models unique human individuals. 72 students aged up across presentations; grouping by `id_student` and tracking lifetime enrollments preserves 1:1 entity resolution while supporting student-level slicing. | Creating duplicate student dimension rows with identical `id_student` or dropping repeat learners. |
| 2026-11-21 | DEC-023 | Explicitly omit spatial / R-Tree indexes across all marts tables. | OULAD contains no GIS vector geometry, latitude/longitude points, or polygon coordinates. Geographic locations are alphanumeric UK region names, which are optimally indexed via standard B-Tree indexes. | Attempting to create artificial spatial columns or R-Tree indexes without coordinate data. |
| 2026-11-22 | DEC-024 | EDA reads from Silver/Gold layers (not raw 10.65M VLE rows) for memory efficiency. | Using pre-aggregated 627k Gold weekly rows and 32k Silver student rows avoids loading 10.65M raw VLE records into Python memory, keeping peak RAM under 1 GB while producing all 17 EDA charts. | Reading raw studentVle.csv (10.65M rows) into memory for each chart, risking MemoryError on constrained systems. |
| 2026-11-22 | DEC-025 | Use Week 5 (end of early warning window) as the reference point for feature correlation heatmap. | Week 5 is the latest point within the early detection window (Weeks 0–5), capturing the most discriminating feature relationships while still being early enough for meaningful intervention. | Using end-of-course features (target leakage risk) or week 0 (insufficient signal). |
| 2026-11-22 | DEC-026 | Native Python backward-chaining inference engine with goal stack and rule decomposition. | University advisors require transparent reasoning for interventions ("why is this student flagged?"). Starting from hypothesis `AT_RISK` and resolving sub-goals produces auditable rule traces while achieving competitive F1 (0.499 vs Logistic Regression 0.546). | Black-box ML models without rule explainability or arbitrary hard-coded procedural if/else blocks. |
| 2026-11-22 | DEC-027 | Data-driven percentile thresholds (P25 severe, P15 critical) stored in external JSON configuration. | Percentile thresholds eliminate arbitrary magic numbers. Disengaged at-risk students cluster at P25-P35, ensuring thresholds dynamically track natural cohort engagement decay across weeks. | Hard-coded magic numbers in source code without empirical statistical derivation. |
| 2026-11-22 | DEC-028 | Longitudinal multi-week risk flag write-back to `marts.fact_risk_flag` (Weeks 1 to 10, 198,493 rows). | Writing back predictions across the full early warning horizon enables Power BI to visualize risk trajectories, progression matrices, and provide a 11-week median lead time before student withdrawal. | Writing back only a single week or storing risk predictions outside the warehouse. |
| 2026-11-22 | DEC-029 | Dedicated `_Measures` DAX calculation table for model governance and folder organization. | Keeps all 23 business KPIs and operational calculations centralized, cleanly decoupled from underlying physical table columns, and simplifies handoff to other developers. | Scattering measures randomly across individual dimension and fact tables. |
| 2026-11-22 | DEC-030 | Portable CSV fallback exports of all 7 dimensional mart objects in `dashboard/export/` (~115 MB). | Enables immediate report authoring and offline evaluation even on workstations where the MySQL database service or Connector/NET is unavailable. | Requiring a live running MySQL instance on every developer/examiner computer. |
| 2026-11-22 | DEC-031 | 5-Page Dashboard visual architecture with dedicated role-based action workflows. | Segregates strategic executive oversight (P1), operational advisor interventions (P2), behavioral telemetry (P3), assessment grading (P4), and institutional demographic equity (P5) to prevent dashboard clutter. | Building a single monolithic cluttered page with competing priorities. |
